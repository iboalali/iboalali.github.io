# `apps.json` — App Manifest Feed

A static, localized JSON feed of the apps showcased on iboalali.com, published
at the site root and fetched by the Android apps (and any other client) to list
and link to sibling apps. This document is the contract for **consumers** and
the guide for **maintainers**. It lives in `docs/` (ignored by Eleventy, not a
published page).

- **Status:** stable
- **Base URL:** `https://iboalali.com`
- **Generated by:** `apps.json.11ty.js` at build time (GitHub Actions → GitHub Pages)
- **Source of truth:** the `app/*.md` detail pages + `_data/` translation files

---

## 1. Endpoints

One file per locale. English is the default and keeps the bare name; every other
locale gets a suffixed file.

| Locale | URL |
| --- | --- |
| English (default) | `https://iboalali.com/apps.json` |
| German | `https://iboalali.com/apps.de.json` |
| Arabic | `https://iboalali.com/apps.ar.json` |
| Spanish | `https://iboalali.com/apps.es.json` |
| Russian | `https://iboalali.com/apps.ru.json` |

The locale list is `_data/locales.json` (`["en","de","ar","es","ru"]`). Adding a
locale there adds a file (see §8).

**Clients must implement fallback:** request the file for the device language;
on `404`, fall back to `/apps.json`. The `locale` field in the response tells you
which locale you actually received.

---

## 2. Response schema

Top-level object:

```jsonc
{
  "locale": "en",      // BCP-47-ish locale code of THIS file ("en","de","ar","es","ru")
  "apps": [ /* App[] */ ]
}
```

Each `App`:

| Field | Type | Notes |
| --- | --- | --- |
| `name` | `string` | Display name, localized. App names stay in English unless a translated name exists (only Arabic for Basic Root Checker today). |
| `packageName` | `string \| null` | Android application id. `null` for web-only apps (e.g. Icon Recomposer). Use it to open the Play Store (`market://details?id=<packageName>` / `https://play.google.com/store/apps/details?id=<packageName>`) or to launch/detect the app on device. |
| `description` | `string` | Short tagline, localized. |
| `icon` | `string` | Absolute URL to a 256×256 PNG. |
| `website` | `string` | Absolute URL. The app's web app if it has one (Icon Recomposer), otherwise its page on iboalali.com. |
| `whatsNew` | `string[]` | The latest "What's New" highlights, localized. May be empty (`[]`). Bullets may contain inline Markdown (e.g. `**bold**`). |
| `changelog` | `ChangelogEntry[]` | Full version history, newest first, localized. |

Each `ChangelogEntry`:

| Field | Type | Notes |
| --- | --- | --- |
| `version` | `string` | Bare version label, e.g. `"2.4"`, `"1.2.2"` (no `"Version"` prefix, no trailing colon). |
| `changes` | `string[]` | Change bullets, in page order. Each keeps its leading status emoji: `➕` added, `🛠️`/`🔧` changed, `🔨` fixed, `➖` removed, `✨` highlight. |

**Ordering:** `apps` is sorted by the app's English name and that order is stable
across all locale files (so index `i` is the same app in every file). `changelog`
is newest-version-first.

**Stability for consumers:** treat unknown fields as additive (don't fail on
them). `packageName` can be `null`. `whatsNew` can be `[]`.

## 4. Localization & fallback semantics

- **Completeness guarantee:** every locale file contains every app and every
  changelog version. Untranslated content falls back to English, so a consumer
  never sees a missing entry.
- **Granularity:** fallback is per *field* and per changelog *version*. An app
  may have a translated `description` but an English `name`; a changelog may have
  translated recent versions and English older ones. (Today all four apps are
  fully translated, but the mechanism is what to rely on.)
- **`locale` field:** reflects the file you fetched, not necessarily the language
  of every string inside it (a string may be an English fallback).

Translations come from two places (documented per app in `_data/appsI18n.js`):

1. **Reused from the app repos' Play Store metadata** where it exists (official
   copy): Basic Root Checker Listing short descriptions + 2.2–2.4 release notes;
   Hide Persistent Notification 2.0 German release notes.
2. **Translated for this site** for everything else. These are not
   professionally reviewed — treat non-English, non-repo strings as best-effort
   until a native pass is done.

## 5. Consuming it (Android)

### Locale selection + fallback

```kotlin
// Map the device language to a manifest URL, with English as the fallback.
private val SUPPORTED = setOf("de", "ar", "es", "ru")  // anything else -> en

fun manifestUrl(lang: String = Locale.getDefault().language): String {
    val base = "https://iboalali.com/apps"
    return if (lang in SUPPORTED) "$base.$lang.json" else "$base.json"
}

suspend fun fetchManifest(client: OkHttpClient): Manifest {
    // Try the device-locale file; on 404 (or any non-2xx) fall back to English.
    val primary = manifestUrl()
    val res = client.get(primary)
    val body = if (res.isSuccessful) res.body else client.get("https://iboalali.com/apps.json").body
    return json.decodeFromString<Manifest>(body)
}
```

### Data model (kotlinx.serialization)

```kotlin
@Serializable
data class Manifest(val locale: String, val apps: List<App>)

@Serializable
data class App(
    val name: String,
    val packageName: String? = null,
    val description: String,
    val icon: String,
    val website: String,
    val whatsNew: List<String> = emptyList(),
    val changelog: List<ChangelogEntry> = emptyList(),
)

@Serializable
data class ChangelogEntry(val version: String, val changes: List<String>)
```

### Opening an app

```kotlin
fun openIntent(app: App): Intent = when (val pkg = app.packageName) {
    null -> Intent(Intent.ACTION_VIEW, Uri.parse(app.website))            // web-only app
    else -> Intent(Intent.ACTION_VIEW, Uri.parse("market://details?id=$pkg"))
        // fall back to https://play.google.com/store/apps/details?id=$pkg if Play is absent
}
```

### Compression

Responses are gzip-compressed by the CDN. `HttpURLConnection` and `OkHttp`
(Retrofit/Ktor-on-OkHttp) add `Accept-Encoding: gzip` and decompress
transparently — you read plain JSON. **Do not set the `Accept-Encoding` header
yourself**, or transparent decompression is disabled and you'll get raw gzip
bytes.

## 6. HTTP / serving characteristics

| Property | Value |
| --- | --- |
| Content-Type | `application/json; charset=utf-8` |
| CORS | `access-control-allow-origin: *` |
| Compression | gzip (per `Accept-Encoding`), `Vary: Accept-Encoding` |
| Caching | `Cache-Control: max-age=600` (10 min CDN/edge) |
| Transport size | ~7–9 KB gzipped per locale file |

Served by GitHub Pages (Fastly edge). Cache is ~10 minutes, so a freshly
deployed change may take that long to propagate at the edge.

## 7. How it's generated

```
app/<slug>.md  ──┐  (frontmatter: appName, icon, packageName, tagline, appUrl?)
                 │  (body: {% whatsNew %} block + ## Changelog section)
_data/locales.json ──┤
_data/appsI18n.js  ──┤   apps.json.11ty.js  ──►  _site/apps.json
                 └──────────────────────────►  _site/apps.<locale>.json
```

- **`apps.json.11ty.js`** — an Eleventy JS template (CommonJS). It:
  1. Paginates over `locales` → one output file per locale; `permalink` is
     `/apps.json` for `en`, else `/apps.<locale>.json`.
  2. Collects `collections.all` filtered to pages with an `appName` (the app
     detail pages) and excludes any with `excludeFromAppsJson: true`.
  3. For each app, reads the page's frontmatter for `name`/`packageName`/
     `description`/`icon`/`website`, and parses the **rendered Markdown body**
     for `whatsNew` (the `{% whatsNew %}…{% endwhatsNew %}` block) and
     `changelog` (the `## Changelog` section, `### Version X:` headings → bullet
     lists). Parsing the body means the feed mirrors what a visitor sees — there
     is no separate English data source to keep in sync.
  4. Applies per-locale overrides from `appsI18n` with per-field and per-version
     English fallback, then sorts by English name.
- **`_data/locales.json`** — the locale list.
- **`_data/appsI18n.js`** — per-locale, per-app overrides, keyed by **page slug**
  then locale: `{ <slug>: { <locale>: { name?, description?, whatsNew?, changelog? } } }`.
  `changelog` is a `{ "<version>": string[] }` map merged onto the English
  changelog per version.

The build output `_site/apps*.json` is **gitignored** — only the template and
`_data/` sources are committed. English content is never duplicated in
`appsI18n.js`; it comes from the page.

## 8. Maintaining the feed

### Add a new app to the feed

1. Create `app/<slug>.md` with the usual app-page frontmatter (`appName`,
   `icon`, `packageName`, `tagline`, and `appUrl` for a web app). It appears in
   **English** in every locale file automatically on the next build.
2. (Optional) Add translations in `_data/appsI18n.js` under the key `<slug>`.

### Keep an app out of the feed

Add to its page frontmatter:

```yaml
excludeFromAppsJson: true   # e.g. work-in-progress apps
```

New apps are included by default; this is the opt-out (currently used by Book
Keeper).

### Add a new locale

1. Add the code to `_data/locales.json` (e.g. `"fr"`). This immediately produces
   `/apps.fr.json` — fully English via fallback until translated.
2. Add the matching `<locale>` block(s) under each app in `_data/appsI18n.js`.
3. Update the client's `SUPPORTED` set (§5).

### Add / update a translation

Edit `_data/appsI18n.js`. Each field is independent and optional:

```js
basic_root_checker: {
  de: {
    description: "…",
    whatsNew: ["…", "…"],
    changelog: { "2.4": ["➕ …", "…"], "2.3": ["…"] }, // version -> bullets
  },
},
```

Omit any field to fall back to English. Omit a changelog `version` key to keep
that version English. Prefer reusing the app's official Play Store release-note /
listing translations verbatim when they exist; the build can only read this
repo, so those strings must be **copied in** here (they can't be read live from
the app repos).

### Conventions

- Keep technical and UI labels in English inside translations (the apps' UIs are
  English): `Export`, `Gradient`, `PNG`, `VectorDrawable`, `Ctrl/⌘`, etc.
- Avoid em dashes in strings (site-copy style); use colons, commas, or parens.
- Preserve the leading status emoji on changelog bullets.

## 9. Design decisions

- **File-per-locale, not one multi-locale file.** ~97% of the payload is
  localizable text (the changelog dominates), so a single file with every
  language inlined would force each device to download all languages and grow
  linearly with locale count. File-per-locale keeps each fetch to one ~7–9 KB
  gzipped file regardless of how many locales exist. The trade-off is a small bit
  of client glue (locale→URL + a 404 fallback).
- **Generated from the page source, not hand-authored.** `whatsNew` and
  `changelog` are parsed from the same Markdown the detail pages render, so the
  feed can't drift from the website. Only *translations* are a separate data
  source.
- **English is the default file (`/apps.json`).** Existing/legacy consumers keep
  working unchanged; localized files are purely additive.

---

## 10. Gotchas

- The generated files are not in the repo — run `npx @11ty/eleventy` and look in
  `_site/` to see them locally.
- `version` labels are bare (`"2.4"`), derived by stripping `Version`/`:` from
  the page's `### Version 2.4:` headings. Keep page headings in that form.
- `icon` URLs may contain `+` in the filename (e.g.
  `basic+root+checker+icon.png`); that is a literal path character and resolves
  as-is.
- App order is by **English** name, so a localized name (e.g. Arabic) does not
  change an app's position across locale files.
